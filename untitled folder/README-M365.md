# إشعارات Microsoft 365 / Outlook

تُحفظ إشعارات صاحب الطلب والمستلم التالي مع انتقال المرحلة داخل معاملة قاعدة البيانات نفسها. يعالجها الخادم المركزي حتى بعد إعادة تشغيله. لا تُرسل رسائل عند غياب إعدادات Microsoft 365؛ تبقى في الانتظار.

## إعداد مسؤول Microsoft 365

1. أنشئ تطبيق مؤسسة في Microsoft Entra ID ودوّن Directory (tenant) ID وApplication (client) ID. أنشئ اعتماداً للتطبيق؛ هذا الإصدار يستخدم قيمة client secret على الخادم فقط، مع تدويرها قبل انتهاء الصلاحية.
2. خصّص صندوق بريد للإشعارات. طبّق صلاحية إرسال البريد للتطبيق وفق إعداد المؤسسة. يدعم Graph صلاحية Application `Mail.Send` بموافقة مسؤول المستأجر. لتقييد الإرسال بصندوق الإشعارات، راجع Exchange Online Application RBAC؛ الصلاحيات الممنوحة من Entra وRBAC تراكمية، فلا تفترض أن نطاق RBAC يقيّد منحة أوسع مستقلة.
3. املأ متغيرات [microsoft365.env.example](microsoft365.env.example) في ملف إعدادات خاص خارج مجلد الموقع والمرفقات، بصلاحية قراءة لمالك الخادم فقط (`chmod 600`). لا تضع قيمة السر في الواجهة أو النسخ المرسلة للموظفين. حمّل المتغيرات في بيئة تشغيل الخادم ثم أعد تشغيله. ملف المثال لا يُحمّل تلقائياً. حالة «الإعدادات مكتملة» تتحقق من وجود القيم وصيغتها فقط؛ أول إرسال يختبر اعتماد Microsoft وصلاحياته.
4. أدخل بريد كل مستخدم من «إدارة المستخدمين». المستخدم النشط ذو البريد الصحيح وصلاحية عرض الطلب يستلم إشعاره. الحساب بلا بريد يُعرض إشعاره كمتوقف؛ يعاد فحصه كل خمس دقائق بعد إصلاح الحساب.
5. ضع عنوان الخادم الداخلي في `SHAMARA_BASE_URL`. روابط الرسائل تفتح الطلب بعد تسجيل الدخول؛ لا تعتمد الطلب بنقرة بريد. يجب أن يصل الموظف إلى شبكة الشركة وأن يثق بشهادة HTTPS.

الاتصال الصادر مطلوب إلى `login.microsoftonline.com` و`graph.microsoft.com` عبر HTTPS. تسجيل دخول الموظفين إلى الداشبورد مستقل عن مصادقة خدمة البريد.

بعد حفظ الإعدادات في الملف الخاص `~/.config/shamara/microsoft365.env`، شغّل الخادم من Terminal ليَرث المتغيرات (أغلق الخادم السابق أولاً):

```zsh
source "$HOME/.config/shamara/microsoft365.env"
"/Users/husseinalbassam/Desktop/Shamara Dashboard /Team_LAN.command"
```

فتح الملف بالنقر المزدوج في Finder لا يحمّل متغيرات جلسة Terminal. شغّل الخادم بهذه الطريقة بعد كل إعادة تشغيل، أو اطلب من مسؤول الخادم ضبط الخدمة لتوريث المتغيرات الخاصة.

## معنى الحالة وإعادة المحاولة

- «قبله Microsoft للإرسال» تعني HTTP 202 من Graph؛ لا تثبت وصول الرسالة إلى صندوق الوارد. يمكن لمسؤول Microsoft متابعة تسليمها من أدوات المؤسسة.
- HTTP 429 وأخطاء الاتصال أثناء طلب رمز الدخول تُعاد تلقائياً، بحد أقصى ست محاولات وتباعد يصل إلى ساعة. أخطاء الصلاحيات والإعداد تبقى متوقفة لتصحيحها.
- عند انقطاع الاتصال أثناء إرسال الرسالة أو توقف الخادم في اللحظة نفسها، قد يكون Microsoft قد قبلها. تُوقف المحاولة الآلية لتجنب رسائل مكررة. يتحقق المدير من الرسائل المرسلة قبل استخدام «إعادة المحاولة»؛ إعادة المحاولة قد تكرر رسالة قُبلت سابقاً.
- إشعار مهمة قديمة لمستلم سابق لا يُرسل إذا تجاوز الطلب مرحلته أو تغيّر المستلم. إشعارات صاحب الطلب التاريخية تبيّن حالة الإجراء وآخر حالة مسجلة.
- لا توجد ضمانة «مرة واحدة تماماً» عبر الشبكة. مفتاح الحدث يمنع إنشاء صف إشعار مكرر، وحجز الصف يمنع عاملين من إرساله بالتزامن. لا يُعاد إرسال الصف الذي تأكد قبوله.
- لا تختبر بإرسال رسالة حقيقية إلا إلى مستلم وافق على الاختبار. الاختبارات المرفقة تستخدم خدمة Microsoft وهمية ولا ترسل بريداً.
